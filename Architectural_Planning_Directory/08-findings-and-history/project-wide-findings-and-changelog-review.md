## Legacy-document reconciliation priorities

The following contradictions recur across architecture and status documents and should be resolved topic-by-topic, preserving original text/history until reviewed:

1. **ICP vs native Axum simulation:** Architecture and audit prose often calls the service a canister/CDK deployment. Current manifests and source show an Axum executable with in-memory state; no ICP deployment metadata/tooling was discovered.
2. **Verified vs simulated:** `MDFILES/system_verification_summary_and_status.md`, `production_readiness_status_and_implementation_roadmap.md`, and `mvp_acceptance_and_live_verification_guide.md` claim live authentication, sub-second DvP, deployed canisters, verified backing, and compliance. The in-app MVP verification component uses timers and hard-coded success strings rather than exercising those systems.
3. **Standard/rail claims vs mappings:** ISO message labels, DTI/ISIN-like values, SWIFT/BIC references, and “certified” exports occur in fixtures/mappings. No real SWIFT/RTGS connector, official identifier assignment, complete standard message implementation, or partner conformance evidence was established.
4. **Gold/custody/PoR claims vs fixtures:** UI and APIs show vault location, weight, purity, Merkle root, and “verified” state, but the inspected endpoint returns constants and no sensor/custodian connection was found.
5. **Privacy/retention assurances vs architecture specification:** GDPR and exact ten-year retention claims are asserted categorically in legacy docs, although actual data flows, jurisdictional scope, legal basis, retention schedule, production PostgreSQL/KMS, and erasure controls were not evidenced.
6. **Role descriptions vs security boundary:** role/persona design tables imply entitlements, while current persona switching is client-side and shared navigation remains. The documented auditor “read-only” posture is not backend enforcement.
7. **Android parity vs device-mode web:** “mobile app” language appears in planning docs; current evidence supports React web/device simulator only, with no native Android package/build.
8. **Current persona inventory:** legacy docs contain differing role counts and an Executive/Mobile Approver role removed per the latest changelog. Current status is seven configured roles per the history and checked source.

The detailed reconciliation checklist is in [`00-overview-and-governance/veritas_bank_program_overview_and_step_by_step_roadmap.md`](../00-overview-and-governance/veritas_bank_program_overview_and_step_by_step_roadmap.md), especially its sections on stop-the-line findings, compliance applicability, test baseline, production gates, related artifacts, and the legacy-document review index.
